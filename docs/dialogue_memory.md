# 单角色长历史记忆

单角色对话采用低频、高低水位压缩。导演和 Stage 使用独立水位的一份共享公开摘要，见[导演共享记忆](director_mode_v1.md#shared-scene-memory)。本文只说明单角色路径。

## 何时压缩，压缩什么

每次生成前，计算当前模型上下文加上本次输入的预计 token 数。默认达到约 600K 时：

1. 固定系统约束和角色 RP 提示词不压缩。
2. 将旧记忆（若有）和较早的原文按时间分段整理为详细记忆，总预算 100K。
3. 优先保留最近 8 个完整轮次，另有 40K token 软预算；超长轮次会使保留轮数减少，不截断本次用户输入。
4. 目标是将新上下文降到 200K 以下；本次输入特别大时允许超过软目标，但仍检查容量与输出预留。
5. 成功后使用“系统及角色设定＋固定历史记忆＋未压缩原文”，随后继续追加新轮次。再次达到高水位才整理下一版。

**最近 8 轮只是一次压缩后的保留起点，不是每轮移动的窗口。**
如果连最近一轮也超出保留预算，可能将全部已完成轮次归入记忆；当前待发送输入始终不压缩。
若本次输入本身无法放入容量，或没有足够旧轮次可压缩，则返回错误，不静默删词。

记忆重点是已确认事实、身份、称呼、偏好、设定，关系变化及原因，按时间排列的重要经历和因果，
承诺、约定、未解决事项、伏笔，当前场景及冲突，以及少量不能失真的原话。
明确区分推测与事实、计划与已经发生的事件、短暂情绪与长期性格，以及各角色的知情范围。
后段更新优先于前段过时状态。记忆作为历史资料传入，不提升成系统指令。

## 分段生成与输出预算

100K 是记忆总预算，不要求模型一次生成 100K，也不是必须凑满的长度。
默认每段约 100K 输入、最多 8 段，串行生成；后段可参考前段记忆理解指代和因果，但不重复抄写。
各段分配总记忆预算，并预留输出空间给模型思考。只安装全部完成的记忆，不使用半份摘要。

摘要使用同一个 `ROLEPLAY_LLM_*` 模型和 API Key，但有独立的 `max_tokens`、超时和重试设置，
不使用角色对白的 JSON 解析、修复或兜底文本。模型思考模式保持供应商默认，不额外关闭。

- 单段初始输出预算 32,768，`finish_reason=length` 时丢弃截断结果，用原始请求扩大到最多 65,536，再试一次。
- 空输出、非 `stop` 终止、超时、超过记忆预算、任务取消或保存失败：不安装新记忆，保留原文与旧记忆。
- 压缩失败且本次输入尚未被后端接收时，前端将它退回草稿/待发送队列，不作为已完成历史缓存。
- 单次尝试有 1,800 秒总时限，关闭 SDK 内部额外重试；不同分段和截断重试分别计时。
- 不自动重试语义不完整的摘要；完整性与角色一致性仍需要真实长会话抽查，token 预算本身不保证质量。

供应商的最大输出限制是 API 的硬上限，以上是项目可配置的任务预算，二者不是同一件事。
输入与最大输出之和也必须符合模型上下文限制，参见 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。
更换模型后必须调整下面的容量和输出参数，不能把 1M 的默认值套在较小模型上。

## 配置

本地 `.env` / HF Variables 的同名值优先于 `.env.template`。无覆盖时使用模板/代码默认值。

| 变量 | 默认 | 含义 |
| --- | ---: | --- |
| `DIALOGUE_COMPACTION_ENABLED` | `true` | 允许生成新记忆；关闭不会删除已有记忆和原文 |
| `DIALOGUE_CONTEXT_MAX_TOKENS` | `1000000` | 所用模型的上下文容量预算 |
| `DIALOGUE_CONTEXT_RESERVE_TOKENS` | `65536` | 输出及估算误差预留 |
| `DIALOGUE_COMPACTION_TRIGGER_TOKENS` | `600000` | 触发高水位 |
| `DIALOGUE_COMPACTION_TARGET_TOKENS` | `200000` | 压缩后软目标 |
| `DIALOGUE_COMPACTION_MEMORY_TOKENS` | `100000` | 所有记忆片段合计预算 |
| `DIALOGUE_COMPACTION_KEEP_TURNS` | `8` | 优先保留最近完整轮次数 |
| `DIALOGUE_COMPACTION_RECENT_TOKENS` | `40000` | 最近原文软预算 |
| `DIALOGUE_COMPACTION_CHUNK_TOKENS` | `100000` | 每段源资料的输入预算 |
| `DIALOGUE_COMPACTION_MAX_CHUNKS` | `8` | 每次任务最多分段数，限制意外大导入的成本 |
| `DIALOGUE_COMPACTION_MAX_TOKENS` | `32768` | 单段首次输出预算，含推理 |
| `DIALOGUE_COMPACTION_MAX_DYNAMIC_TOKENS` | `65536` | 截断重试最大输出预算 |
| `DIALOGUE_COMPACTION_LENGTH_RETRIES` | `1` | 单段截断重试次数 |
| `DIALOGUE_COMPACTION_TIMEOUT_SECONDS` | `1800` | 每次尝试总时限 |

必须满足 `记忆预算 < 目标水位 < 触发水位 < 容量`，并留出足够输入及输出空间。
启用压缩时忽略 `DIALOGUE_SESSION_HISTORY_MAX_MESSAGES` 的旧裁剪设置，完整归档不能被滑窗截短。
关闭压缩、但仍希望读取已有记忆时，应保持该旧设置为 `0`。

token 判断使用 UTF-8 字节估算，并利用正常回复的实际 `usage.prompt_tokens` 校准、加安全余量；
不是供应商 tokenizer 的精确计数。输入语言、代码或编码内容明显变化时仍可能估算不准，应保守设置水位。

## 缓存与恢复

完整聊天原文一直保留在会话及后端 JSONL 中。压缩只切换模型读取视图，不删除原文。
浏览器将完整原文与对应的 `context_checkpoint` 放进同一条 IndexedDB 事务，避免摘要和原文错配。
旧 localStorage 缓存自动迁移，只有新存储写入成功才移除旧副本；存储满或权限失败会显示警告。
音频文件、Blob 和播放 URL 不写进这份缓存，只保留原有 TTS 任务引用。

- 后端仍有文件：加载角色时恢复全文，并校验最新 checkpoint。
- HF 重启且后端历史为空：加载角色后，前端自动将该浏览器的全文与记忆重新导入。
- JSON / Markdown 导出包含全文、记忆与可验证的原始模型 JSON；旧导出文件没有记忆也能导入。
- 编辑/重新生成最后一轮：只要已压缩的原文前缀未改变，就保留记忆。修改已覆盖的旧内容或导入不匹配历史，则丢弃旧记忆，保留原文，之后按阈值重新生成。
- checkpoint 校验浏览器 UUID、角色 ID、提示词指纹、覆盖消息数量及原文摘要哈希。换浏览器/角色导入仍可导入原文，但不能沿用原浏览器的记忆。
- 清理当前角色历史同时清掉记忆和缓存。替换导入是新的完整历史版本，恢复时不会把老版本再拼一次。

### 历史时间与恢复顺序

单角色的历史展示、会话恢复、替换/清空边界和 checkpoint 选择按解析后的实际时间比较，
支持 `Z`、`+08:00` 等 ISO 时区偏移。新 JSONL 事件的 `timestamp` 写为带 `+00:00` 的 UTC 时间；
导入文件原来的时间仍保存在 `imported_timestamp`，不会被当作本次写入或重置时间。

旧版没有时区的 `timestamp` 按后端运行环境的本地时区解释，延续原来的 `datetime.now()` 语义，
并使用该历史日期的时区偏移。直接将旧 JSONL 搬到另一时区的服务器前，需要按原服务器时区补齐偏移；
程序不能从无时区的文本推断原时区。常规浏览器/文件导入会重新记录落盘时间，不属于直接搬迁 JSONL。

相同时间使用 session ID、数值化消息索引作确定性排序；索引相同或缺失时保留稳定的文件/行顺序。
这不能推断完全同一时刻跨 session 的真实因果顺序。缺失或损坏的时间排在有效时间之前；
它们不能作为重置边界，也不会仅因无法判断早晚而丢弃消息。读取不改写旧文件或对外时间字段。

HF 不需要外接数据库或持久盘。JSONL 只是快速恢复副本，浏览器缓存也可能被清理或淘汰，重要长会话仍建议定期导出备份。
这不是账号认证系统：仍沿用浏览器 UUID 的隔离方式，不新增跨浏览器共享。

## 在聊天记录中检查压缩

成功压缩后，聊天时间线会在**实际触发位置**增加一条带小箭头的“历史压缩 · 第 N 版”。
点击可展开/收起摘要、生成时间、覆盖消息范围和当时保留的近期原文范围。
默认收起，展开后摘要区域独立滚动；摘要以纯文本显示，不执行其中的 HTML。

`trigger_message_count` 记录本次发送前已有的消息数，与 `covered_messages`（被摘要替代的早期前缀长度）分开。
例如原来有 100 条消息，摘要覆盖前 84 条、保留后 16 条原文，标记就在第 100 条之后、新输入之前，
而不是第 84 条之后。标记只是展示行，不进入聊天原文，不影响轮数、重生成、TTS 和模型消息。

各版摘要作为 `context_checkpoints` 随 JSONL、IndexedDB 和 JSON/Markdown 导出保存。
只有 `context_checkpoint` 指向的当前版本供模型使用，历史版本不会叠加进 prompt。
导入、修改或裁剪历史后，会按浏览器/角色与原文指纹剔除不匹配的展示快照；清空历史也清空标记。
旧版摘要若没有记录触发位置，或该位置已被裁剪，只在覆盖范围末尾展示并明确标注，不推测触发位置。

**已有长历史不在加载、刷新、查看或导入时自动压缩。** 下一次发送时若达到阈值，才在旧历史末尾触发。
现有有效记忆继续沿用；再次达到阈值时整理旧记忆和之后新增长的原文。既不改写旧聊天内容，
也不因为检查历史而调用模型或产生额外压缩费用。

## 前缀缓存、用量与接口

系统提示词不变；压缩完成后记忆不再逐轮修改，新增消息只追加在末尾。
周期格式提醒保留原来的绝对消息位置，恢复时尽量保留经过字段校验的原始模型 JSON，避免格式化改变缓存前缀。
压缩会使旧历史前缀失效一次，之后重新积累稳定前缀；不能保证供应商每次命中。
参见 [DeepSeek 缓存规则](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。

压缩请求与该轮角色回复归入同一次浏览器用量操作；初次压缩可能明显变慢、增加当轮用量，后续轮次输入则减少。
日志记录 `purpose=dialogue_compaction`、压缩开始/提交、版本、覆盖数、分段数和估算 token，不打印摘要正文。

旧请求字段、入口与部署命令不变，新增内容为可选字段/事件：

- `/capabilities` 增加 `dialogue_memory=1`。
- `/load_character`、`/history/import` 返回 `context_checkpoint` 和展示用 `context_checkpoints`；导入时可携带它们。
- `/chat` 与 `structured_reply` 可返回新 checkpoint；消息中可包含 `model_content`。
- SSE 新增 `context_status`（`compacting` / `compacted`），并每 15 秒发送 keepalive 注释；其余事件顺序不变。
- `GET /session/{session_id}/context?user_uuid=...` 用于恢复/失败后的 checkpoint 同步，不做高频轮询。

推荐长会话使用 SSE，以获得整理进度并保持代理连接。非流式接口仍可用，但代理自身的请求时限仍可能截断长任务。
生产前端仍由同一份 `frontend/` 构建，GitHub Pages 与 HF 工作流、依赖锁文件均未调整。

```bash
uv run python -m unittest discover -s tests -q
cd frontend
pnpm test
pnpm build
```

覆盖连续压缩、稳定前缀、超长输入、截断重试、失败/取消、JSONL/浏览器恢复、重生成、隔离、清理、缓存迁移及导入导出。
这些测试使用假模型，不消耗 API 额度；不代替真实模型的记忆保真度评估。
